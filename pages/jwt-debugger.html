JWT 架构与企业级安全防线 (RFC 7519 / RFC 8725)

JSON Web Token (JWT) 是一种紧凑且自包含的安全传输格式。Token 由以 . 分隔的三个部分组成：Base64URL(Header) . Base64URL(Payload) . Signature。需要明确的是，Payload 默认仅做了 Base64 编码，并未加密，任何截获者均可解码读取明文。

🛠️ 三大核心组件

  • Header：声明令牌类型（typ: "JWT"）及签名算法（如 HS256、RS256）。
  • Payload：承载标准 Claims（如 sub 用户ID、exp 过期时间戳）与业务 Claims。
  • Signature：通过私钥或共享 Secret 对头部和载荷计算的数字签名，确保数据不被篡改。

🛡️ 安全开发清单

  • 严禁存储机密信息：切勿在 Payload 存放用户明文密码、银行卡或内部敏感凭据。
  • 防御 alg: none 攻击：后端鉴权时必须强制校验预期算法，杜绝无签名伪造漏洞。
  • 必须限制有效期：生产 Access Token 建议设为 15~60 分钟短效期，配合 Refresh Token 轮换。
