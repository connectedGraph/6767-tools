# 6767 开源站 - 在线工具集

6767 开源站是一个综合性在线工具集合平台，致力于收录与整理各类高效、实用的在线工具与轻量应用。全站资源高度本地化，支持离线开箱即用，注重隐私安全与纯粹交互体验。

- **官方在线体验站点**：[https://TOOL.6767.chat](https://TOOL.6767.chat)
- **开源协作与投稿**：欢迎提交 Issue 投稿新工具、推荐优质功能或提交优化建议。

---

## 平台特性

- **工具收录全面**：收录包含脑力训练、办公助手、图像处理、音视频处理、生成器、程序员开发辅助、学习计算、生活便民、娱乐休闲、健康管理等多个大类的百余款实用工具。
- **全资源本地化**：前端框架、第三方依赖库（Vue 3、Element Plus、Monaco Editor、ImageMagick 等）、图标资源（SVG/PNG）、字体与模板文件均完整内置，零外部网络依赖，支持完全离线部署。
- **轻量双模运行**：
  - **动态完整模式**：基于 Node.js 原生 HTTP 模块实现 Clean-URL 静态路由与内置轻量 Mock API（支持本地用户体系、历史记录、游戏榜单与数据持久化）。
  - **纯静态模式**：提供单文件静态文件服务器，适用于快速托管与无后端环境。
- **一致的交互体验**：全站适配现代深色终端风格，响应式布局适配桌面端与移动端浏览器。

## 独立部署包 (Standalone)

为了方便不想配置 Git 环境或希望快速容器化自托管的用户，本项目提供了开箱即用的 **Standalone 独立部署方案**：

### 1. GitHub Releases 独立离线便携包

前往 [GitHub Releases 页面](https://github.com/connectedGraph/6767-tools/releases) 下载最新的 `6767-tools-v1.0.0-standalone.zip`：
- **免 Git / 零 npm 依赖**：下载解压即可直接运行，无需克隆仓库，无需执行 `npm install`。
- **双击一键运行**：
  - **Windows 用户**：双击根目录下的 `start.bat`（自动检查运行环境、启动服务并自动打开浏览器）。
  - **Linux / macOS 用户**：终端赋予执行权限后运行：`chmod +x start.sh && ./start.sh`。

### 2. Docker / Docker Compose 容器化一键部署

无需在宿主机配置 Node.js 环境，直接通过容器启动完整服务：

```bash
# 方式一：使用 Docker Compose 一键启动（推荐）
docker compose up -d

# 方式二：使用原生 Docker 命令构建与运行
docker build -t 6767-tools .
docker run -d -p 8093:8093 -v $(pwd)/_server_data:/app/_server_data --name 6767-tools 6767-tools
```

启动完成后访问 `http://localhost:8093/`，用户数据与文件上传将自动持久化至本地挂载卷。

## 快速开始（源码克隆方式）

### 环境依赖

- Node.js 18.x 或更高版本（纯原生模块，零 npm 依赖）

### 运行方式

#### 1. 启动主服务器（推荐）

提供 Clean-URL 路由映射以及本地 Mock API 接口支持：

```bash
node server.js
```

默认监听端口为 `8093`。如果需要指定自定义端口，可在命令后传入端口参数：

```bash
node server.js 9000
```

启动完成后，通过浏览器访问：
- 站点主页：`http://localhost:8093/`
- 工具详情页（支持 Clean-URL 免 `.html` 后缀）：`http://localhost:8093/age`、`http://localhost:8093/md5-encrypt` 等。

#### 2. 启动备用纯静态服务器

适用于无需本地 API 接口、仅浏览与使用纯静态纯前端工具的场景：

```bash
node serve_deploy.js
```

默认监听端口为 `8080`。

## 参与贡献与 Issue 投稿

6767 开源站是一个持续成长的工具收录项目，非常欢迎社区力量参与共建：

### 1. 提交新工具需求 / 投稿

如果您发现好用的工具需求、或希望站内收录某款特定功能：
1. 前往 GitHub Issues 页面；
2. 新建 Issue，标题格式建议为：`[工具投稿] 工具名称 - 简要概述`；
3. 在正文中简述：
   - 工具名称与主要使用场景；
   - 核心功能点与预期输入/输出；
   - 参考链接或现有实现思路（如有）。

### 2. 提交代码与 Pull Request

1. Fork 本仓库并克隆到本地；
2. 新增页面放置于 `pages/` 目录下，静态依赖统一存放在对应公共目录；
3. 工具页面建议保持轻量独立、避免引入外部 CDN 强依赖；
4. 提交清晰规范的 Commit 信息并提交 Pull Request。
